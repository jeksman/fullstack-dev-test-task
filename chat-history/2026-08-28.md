## Задача 2 — ghost-hetzner-oneclick
- Просьба: в `task2/` собрать production-проект «одна команда → Ghost на Hetzner», где публичный SSH не открывается никогда; интерактивный визард из 12 шагов, доступ только через Tailscale, полная верификация, тесты, документация. Дополнительно — папка `conversation/` с историей диалога.
- Проверены официальные источники перед кодом: Ghost 6.x требует Node 22 LTS, Ubuntu 22.04/24.04/26.04, MySQL 8.0/8.4, nginx ≥1.9.5; hcloud CLI 1.67.0; jq 1.8.2; Tailscale 1.102.3; поддержка `--auth-key=file:` подтверждена в исходниках `cmd/tailscale/cli/up.go`. Зафиксировано в `docs/version-matrix.md` с датой проверки.
- Архитектура: firewall создаётся ДО сервера и прикрепляется в самом запросе `server create` — окна без фильтрации не существует. Stage 1 (cloud-init) поднимает только приватный доступ: `ghostops`, ключ, hardening sshd, ufw (22 только на `tailscale0`), вход в tailnet одноразовым ключом, уничтожение ключа. Stage 2 целиком идёт через туннель.
- Инвариант «нет публичного SSH» защищён структурно: `rssh`/`rscp` вызывают `ssh_assert_private_target`, пропускающий только `100.64.0.0/10` и явно отвергающий записанные публичные адреса сервера. Проверка закрытости порта 22 выполняется трижды — после создания, после установки и после ребута; срабатывание = containment (poweroff + возврат жёстких правил).
- Секреты нигде не попадают в argv: ключ Tailscale через `file:`, SQL из 0600-файлов, Cloudflare через `curl --config`, редактор логов собирает sed-программу в 0600-файле. Единственное исключение — `ghost install --dbpass` (у Ghost-CLI нет альтернативы), поэтому пароль после установки ротируется на второй сгенерированный через 0600-файлы.
- Ghost работает под `ghostops` (`--no-setup-linux-user`), не под root и не под пользователем `ghost`.
- Реализованы `--resume`, `--dry-run`, `--status`, `--destroy`, `--non-interactive`, `--keep-on-failure`; состояние атомарное, с локом и пропуском выполненных стадий. Стадии preflight/credentials/settings выполняются всегда — они наполняют сессию.
- Тесты выполнены: `bash tests/run.sh` — 14 файлов, 378 проверок, 0 падений; ShellCheck чист; shfmt без расхождений (бинарь загружен в `.tools/bin`, чтобы проверка реально прошла). Дополнительно прогнаны `--dry-run`, `--status`, `--resume` и `--destroy` на моках; `--destroy` корректно отказался трогать ресурсы с чужим `deployment-id`.
- Тесты нашли и починили реальные баги: `\|` в BSD sed (редакция секретов молча не работала на macOS), приоритет операторов в jq (обнаружение узла Tailscale падало бы всегда), три `A && B` на уровне statement, убивавших скрипт под `set -e` при успешной проверке, и утечка токена Hetzner в argv.
